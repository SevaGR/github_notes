# Τι είναι το Git

Το Git είναι ένα Version Control System (VCS) που αποθηκεύει τις αλλαγές που γίνονται σε αρχεία. Προσφέρει δυνατότητες όπως το να επισκεπτόμαστε παλιότερες εκδόσεις αρχείων μας, συγκρίσεις μεταξύ εκδόσεων, ακύρωση αλλαγών και επιστροφή σε παλιότερες εκδόσεις και πολλά άλλα.

Τρέχει locally στο σύστημα του κάθε χρήστη, δε χρειάζεται να έχεις account, δε χρειάζεται internet και μπορεί να χρησιμοποιηθεί χωρίς το Github.

Το Github είναι μία υπηρεσία που κάνει host Git repositories (Git αποθετήρια;) στο cloud και κάνει πιο εύκολη τη συνεργασία μεταξύ των χρηστών.

- Κάθε φάκελος, υποφάκελος, αρχείο κλπ που δημιουργούμε μέσα σε ένα git repository, ανήκει στο repository. Δεν ξανακάνουμε git init! Πρώτα ελέγχουμε με το git status και αν δεν είναι ήδη repository, τότε κάνουμε το initialize.

- Με το `git add` ετοιμάζουμε (staging) τις αλλαγές που θέλουμε να κάνουμε στα αρχεία μας ΠΡΙΝ κάνουμε το commit. Μπορούμε να κάνουμε `add` πολλά αρχεία μαζί βάζοντας ένα κόμμα ανάμεσά τους ή αφήνοντας κενά.

- Με το commit δημιουργούμε "στιγμιότυπα" των αλλαγών που έχουμε κάνει στα αρχεία μας. Δεν είναι το ίδιο με το να σώζουμε ένα αρχείο. Αφού έχουμε κάνει τις απαραίτητες αλλαγές και αποθηκεύσεις στα αρχεία μας, μπορούμε να κάνουμε commit. Για την ακρίβεια μπορούμε να κάνουμε commit πολλά αρχεία μαζί και ακόμα και να τα ομαδοποιήσουμε (π.χ. με βάση μια συγκεκριμένη δουλειά που κάναμε - κάποιο κοινό τους χαρακτηριστικό). 

- Το βασικό workflow είναι το εξής. Δημιουργούμε ένα αρχείο (ή πολλά) ή επεξεργαζόμαστε ένα ήδη υπάρχων, κάνουμε τις όποιες αλλαγές και το αποθηκεύομε. Αυτό βρίσκεται στο Working Directory. Με την εντολή `git add` το βάζουμε στο Staging Area, ένα μη υπαρκτό φυσικό μέρος όπου βάζουμε τα αρχεία τα οποία θέλουμε να κάνουμε commit. Με την εντολή `git commit` κάνουμε τελικά το commit και πάνε οι αλλαγές στο Repository.

- Προτού ολοκληρωθεί το commit, θα ανοίξει ο default text edditor για να γράψουμε το commint message. ΟΛΑ τα commints πρέπει να έχουν σύντομο περιγραφικό μήνυμα των αλλαγών που έγιναν σε αυτό το commit. Με το flag `-m` μετά το `git commit` μπορούμε να δώσουμε κατευθείαν το commit message.

- Το documentation έχει λεπτομέρειες για όλες τις εντολές και τα options τους (με παραδείγματα).

- Συστήνεται να γίνονται "ατομικά" commits, να είναι δηλαδή αλλαγές σε ένα συγκεκριμένο πράγμα (feature) για να είναι πιο εύκολο αργότερα να γίνουν αλλαγές ή επιστροφές σε αυτό το σημείο. Να μη γίνονται commit διαφορετικές εργασίες/αλλαγές.

- Στα commits συστήνεται να υπάρχει μία σύντομη γραμμή σαν summary και μετά να ακολουθούν με κενά οι λεπτομέρειες.


#### Ammending Commits

Αν κάνουμε κάποιο λάθος, πχ ξεχάσαμε να κάνουμε commit κάποιο αρχείο ή κάναμε λάθος στο μήνυμα, μπορούμε να κάνουμε ammend. ΟΜΩΣ λειτουργεί ΜΟΝΟ με το τελευταίο commit που κάναμε. Δε γίνεται να κάνουμε αλλαγή σε προ-προηγούμενο commit ή κάποιο παλιότερο. Αυτό γίνεται με την εντολή `git commit --amend`. 

#### Αρχεία που αγνοούνται

Κάποιες φορές ίσως υπάρχει λόγος να αγνοήσουμε κάποια αρχεία από το repository μας. Μπορεί να είναι ευαίσθητα αρχεία που θέλουμε να τα κάνουμε commit, κάποια αρχεία που ίσως να ενημερώνονται συχνά και να μη θέλουμε το Git να ψάχνει για αλλαγές σε αυτά ή μπορεί να είναι system files. Αυτό γίνεται με ένα αρχείο **.gitignore** στο βασικό (root) φάκελο του repository. Μέσα σε αυτό βάζουμε τα αρχεία που θέλουμε να αγνοηθούν.

Για παράδειγμα: 
- **.DS_STORE** - θα αγνοήσει τα αρχεία με όνομα .DS_STORE
- `folderName`/ - θα αγνοήσει το συγκεκριμένο directory (φάκελο) 
- `*.log` - θα αγνοήσει φακέλους με το .log extension

Πως το κάνουμε:
- Δημιουργούμε το αρχείο (είτε όπως ξέρουμε) είτε στη γραμμή εντολών με `touch .gitignore`
- Μέσα στο αρχείο αυτό γράφουμε αυτά που θέλουμε να εξαιρεθούν (είτε αρχεία είτε φακέλους), π.χ.: 
	- .DS_STORE
	- secrets.txt
	- node_modules


# Branching

Μπορούμε να φανταστούμε τα brances σαν εναλλακτικά timelines του project. Μπορούμε να δοκιμάσουμε διαφορετικά πράγματα, να κάνουμε αλλαγές, προσθήκες, αφαιρέσεις κλπ χωρίς να επηρεάζεται το βασικό project. Οι αλλαγές σε ένα branch δεν επηρεάζουν τα υπόλοιπα (εκτός και αν τα κάνουμε merge).

Το πρώτο branch που δημιουργείται αυτόματα με το `git init` είναι το master. Το branch στο οποίο βρισκόμαστε εκείνη τη στιγμή φαίνεται με έναν αστερίσκο. Για να δούμε τα branches χρησιμοποιούμε την εντολή `git branch`. 

##### HEAD
Ο όρος HEAD είναι ένας δείκτης που αναφέρεται στην τωρινή μας θέση στο repository. Κάθε branch έχει το δικό του pointer, το δικό του "σελιδοδείκτη". Το HEAD δείχνει στην σελίδα που έχουμε ανοιχτή αυτή τη στιγμή (στο branch που δουλεύουμε) και αν πάμε σε άλλο σελιδοδείκτη (branch), το HEAD θα δείξει εκεί. Συγκεκριμένα το HEAD δείχνει στο τελευταίο commit στο συγκεκριμένο branch που είμαστε (η "τιμή" του είναι το hash από το τελευταίο commit του branch).

##### Δημιουργία καινούργιου branch

Με τη χρήση της εντολής `git branch <branch-name>` δημιουργείται ένα καινούργιο branch, ωστόσο παραμένουμε στο branch που είμαστε ήδη (δε μπαίνουμε δηλαδή αυτόματα στο καινούργιο - το HEAD δείχνει ακόμα στο τωρινό μας branch). Το καινούργιο branch θα δημιουργηθεί εκεί που δείχνει το HEAD.

##### Switch και checkout

Για να πάμε από ένα branch σε ένα άλλο χρησιμοποιούμε την εντολή `git switch <branch-name`
Αν κάνουμε commit μετά από αλλαγή σε άλλο branch, η αλλαγή αυτή θα γίνει στο τωρινό (καινούργιο) branch. Αν επιστρέψουμε στο master branch, οι αλλαγές που κάναμε commit στο child branch δε θα φαίνονται.

Πριν πάμε από ένα branch σε ένα άλλο, πρέπει να σιγουρευτούμε ότι έχουμε κάνει commit τις αλλαγές μας. Αν ένα αρχείο σε ένα branch δεν υπάρχει σε άλλο branch (αν δηλαδή δεν υπάρχει conflict) και δεν το κάνουμε commit στο branch που είμαστε πριν την αλλαγή, όταν κάνουμε `switch`, το αρχείο αυτό θα μας ακολουθήσει στο branch που θα πάμε. Αν υπάρχει σε άλλο branch (υπάρχει conflict), τότε πρέπει ή να το κάνουμε commit ή stash.

Αντί για την εντολή `switch` μπορούμε να χρησιμοποιήσουμε την εντολή `git checkout`. Αυτή είναι και η original εντολή για να αλλάξουμε branch, αλλά επειδή έχει και πολλές άλλες λειτουργίες, δημιουργήθηκε και προτιμάται η switch. Η `checkout` μπορεί να χρησιμοποιηθεί για τη δημιουργία ενός branch, για να πάμε σε ένα άλλο branch, για να κάνουμε restore files και για να κάνουμε undo history.

# Merging

Συνήθως δουλεύουμε σε feature branches και όχι στο main (για να μη το χαλάσουμε) και όταν νιώθουμε έτοιμοι να ενώσουμε τα νέα features με το main πρόγραμμα, κάνουμε merge τα branches. 
- Κάνουμε merge branches, όχι commits.
- Κάνουμε merge στο τωρινό HEAD branch.

### Fast Forward Merge

Στην περίπτωση που κάνουμε merge ένα "child" branch, με για παράδειγμα, το master branch, και το master δεν έχει δεχτεί αλλαγές (commits) από την ώρα που φτιάχτηκε το child branch, τότε έχουμε την περίπτωση του fast forward merge. Είναι δηλαδή σαν το branch στο οποίο κάνουμε το merge, να προφτάνει (τις αλλαγές σ)το child branch. Για παράδειγμα για να κάνουμε merge ένα branch (έστω με όνομα bugfix) στο master, κάνουμε πρώτα switch στο master και μετά με την εντολή `git merge bugfix` κάνουμε το merge. Ουσιαστικά κάνουμε `switch` στο destination merge, εκεί που θέλουμε να μπουν οι αλλαγές και κάνουμε `git merge <branch-name>` το branch από το οποίο θέλουμε να πάρουμε τις αλλαγές. Μετά το merge το child branch συνεχίζει να υπάρχει.

## Περιπτώσεις που δεν έχουμε Fast Forward Merge

### Merge Commit

Όταν θέλουμε να κάνουμε merge ένα branch σε ένα άλλο το οποίο όμως έχει υποστεί αλλαγές (δηλαδή το branch από το οποίο θα γίνει το merge, ξεκίνησε από προηγούμενο commit του branch στο οποίο θα γίνει branch), αν δεν έχουμε conflicts μεταξύ των branches τότε γίνεται το merge commit. Το καινούργιο commit θα έχει 2 parent commits, ένα από το branch που κάνουμε merge και ένα από το branch στο οποίο θα γίνει το merge. Σε αυτό βάζουμε κανονικά μήνυμα όπως θα κάναμε σε ένα οποιοδήποτε commit. 

### Conflicting Merges

Αν προσπαθήσουμε να κάνουμε merge δύο branches που μεταξύ τους έχουν κάποιο conflict, π.χ. στο ένα branch να υπάρχει ένα αρχείο και στο άλλο να έχει σβηστεί ή στη γραμμή 55 στο ένα branch να έχω γράψει κάτι και στο άλλο branch να έχω γράψει κάτι άλλο, τότε για να προχωρήσει το merge, θα πρέπει πρώτα να επιλυθούν τα conflicts.

Η διαδικασία είναι η εξής:
- Ανοίγουμε τα αρχεία με το conflict
- Κάνουμε edit τα αρχεία ώστε να μην υπάρχουν πλέον conflicts. Πρέπει να αποφασίσουμε τι θέλουμε να κρατήσουμε από τα conflicts.
- Αφαιρούμε τα conflict markers από το αρχείο.
- Κάνουμε ότι άλλες αλλαγές θέλουμε και κάνουμε το commit. 

# Diff

Με την εντολή `git diff` μπορούμε να δούμε αλλαγές που έχουν γίνει μεταξύ commits, branches, files, directories κ.α.. Συνήθως το χρησιμοποιούμε μαζί με άλλες εντολές όπως `git status` και `git log` για να καταλάβουμε τι έχει αλλάξει σε ένα repository.

Για να καταλάβουμε τι μας δείχνει το diff θα χρειαστεί να καταλάβουμε το πως εμφανίζει το output. Το ένα αρχείο θα ξεκινάει με a/... και το άλλο με b/..., οι αλλαγές στο πρώτο (α) θα εμφανίζονται με ένα μείον(-) και στο δεύτερο (b) με ένα συν (+). Η γραμμή που έχει τα @@ "μεταφράζεται" ως εξής. Ας υποθέσουμε ότι έχουμε το εξής παράδειγμα:

@@ -3,4  +3,5 @@ -> το -/+ υποδηλώνει το αρχείο στο οποίο αναφέρεται η αλλαγή, δε σημαίνουν πλην/συν. Το 3 σημαίνει "ξεκινώντας από τη γραμμή <3> (στον κώδικα)" και το 4/5 σημαίνει ότι σε εκείνη τη γραμμή υπάρχει αλλαγή. Αυτό δε σημαίνει ότι η γραμμή 3 έχει αλλάξει, απλά έτσι επιλέγει το Git ένα σημείο που διαβάζει τις αλλαγές (παίρνει ένα chunk - κομμάτι). Για παράδειγμα:

red
orange(προηγούμενο κομμάτι κώδικα που εμφανίζεται με το git diff και χωρίς να έχει αλλάξει)
yellow (3η γραμμή που ξεκινάει το chunk που επέλεξε το Git)
green
blue
-purple
+indigo
+violet

Αυτό σημαίνει ότι στο πρώτο αρχείο (α) υπάρχει το purple (το καταλαβαίνουμε από το - στην αρχή) αλλά όχι τα επόμενα και στο δεύτερο αρχείο (b) δεν υπάρχει το purple αλλά υπάρχουν τα indigo και violet. Στην περίπτωση αυτή το Git ξέρει ότι το purple είναι στο staging area (πρέπει να έχει γίνει add) ενώ τα άλλα δύο είναι τώρα στο working directory.

Αν κάνουμε stage τις αλλαγές, τότε το `git diff` δε θα δείξει κάτι, λειτουργεί μόνο σε αλλαγές που έχουν γίνει ΠΡΙΝ κάνουμε stage το αρχείο. Αν θέλουμε να δούμε τις αλλαγές στα staged files χρησιμοποιούμε το `git diff --staged/cached`. Με την εντολή `git diff HEAD` μπορούμε να δούμε τις αλλαγές που έχουν γίνει από το τελευταίο commit, άρα και αυτές που έχουν γίνει staged και τις unstaged. Οπότε αν κάνουμε commit τα τελευταία χρώματα, το `git diff` δε θα δείξει κάτι, αλλά το `git diff HEAD` θα δείξει ότι βλέπουμε και πιο πάνω.

# Stashing

Το stashing χρησιμεύει όταν σε ένα branch έχουμε κάνει κάποιες αλλαγές και θέλουμε να γυρίσουμε σε ένα άλλο, χωρίς όμως να κάνουμε commit τις αλλαγές σε αυτό και ενώ μεταξύ των branches υπάρχουν conflicts. Γενικά όταν υπάρχουν conflicts και θέλουμε να αλλάξουμε branch, ενώ δεν έχουμε κάνει commit, παίρνουμε ένα μήνυμα λάθους που μας προτρέπει ή να κάνουμε commit ή να κάνουμε stash. Αν δεν υπάρχουν conflicts, τα αρχεία θα έρθουν μαζί μας στο άλλο branch.
#### stash (save)

Με το `git stash (save)` μπορούμε να αποθηκεύσουμε αυτές τις αλλαγές (κάπου) χωρίς να κάνουμε commit. Όλες οι uncommited αλλαγές (staged και unstaged) θα αποθηκευτούν (κάπου). Όμως μετά το stashing, το working directory και το staging area σε αυτό το branch, θα μείνουν κενά, ενώ τα αρχεία μας και οι αλλαγές σε αυτά θα υπάρχουν "κάπου" από όπου θα μπορούμε αργότερα να τα ανακτήσουμε. 

Μπορούμε να κάνουμε stash πολλές φορές, πολλά διαφορετικά αρχεία και αλλαγές και κάθε φορά θα μπαίνουν σε μία στοίβα από stashes. Δηλαδή το τελευταίο stash θα είναι πρώτο στη στοίβα από stashes. Για να δούμε τι έχει αποθηκευτεί στη στοίβα από stashes, χρησιμοποιούμε την εντολή `git stash view`. 
#### pop

Μπορούμε να ανακτήσουμε τις αλλαγές που κάναμε stash με την εντολή `git stash pop`. Αυτές οι stashed αλλαγές μπορούν να "ξαναμπούν" sto working directory που τις κάναμε ή μπορούν να μπουν και σε κάποιο άλλο εντελώς branch. Η `pop` αφαιρεί το πιο πρόσφατο stash σε περίπτωση που έχουμε πολλά.
#### apply

Υπάρχει και η δυνατότητα να πάρουμε ότι υπάρχει στο stash, να το επιστρέψουμε κάπου, αλλά ότι υπήρχε στο stash, να παραμείνει εκεί. Αυτό το κάνει η εντολή `git stash apply` που κάνει apply τις αλλαγές που υπάρχουν στο stash, σε κάποιο branch, όμως το stash δεν αδειάζει. Έτσι μπορούμε να πάμε σε ένα άλλο branch και να χρησιμοποιήσουμε και εκεί ό,τι υπάρχει στο stash.

Αν έχουμε πολλά stashes, μπορούμε να πάρουμε κάποιο συγκεκριμένο κάνοντας reference το συγκεκριμένο "id" του π.χ. `git stash apply stash@{2}`.

#### drop και clear

Για να αφαιρέσουμε ένα συγκεκριμένο stash χρησιμοποιούμε την εντολή `git stash drop <stash-id>`, π.χ. `git stash drop stash@{2}`.

Για να σβήσουμε όλα τα stashes χρησιμοποιούμε την εντολή `git stash clear`.

# Reverting Changes and Time Travelling

### Time travelling

Για να δούμε ένα παλιότερο commit μπορούμε να κάνουμε χρήση της `git checkout <commit-hash>` ενώ το hash το παίρνουμε από το git log (χρειαζόμαστε τα 7 πρώτα ψηφία). Αφού εκτελέσουμε την εντολή, το Git μας λέει ότι είμαστε στο "detached HEAD". Το HEAD έχουμε πει πάλι ότι είναι ένας δείκτης σε ένα branch reference το οποίο με τη σειρά του είναι δείκτης σε ένα commit. Με την παραπάνω εντολή, το HEAD γίνεται δείκτης σε ένα συγκεκριμένο (παλιότερο) commit, για αυτό ονομάζεται detached HEAD. Από εκεί μπορούμε να δούμε τα αρχεία και τα παλιά commits, μπορούμε να επιστρέψουμε στην αρχική κατάσταση (reattach the HEAD με `git switch`) ή ακόμα και να φτιάξουμε ένα καινούργιο branch στο οποίο θα μπορούμε να κάνουμε κανονικά αλλαγές αφού το HEAD δε θα είναι πλέον detached.

Υπάρχει και το syntax `git checkout HEAD~<commit reference>`. Αν είμαστε πχ στο HEAD, μπορούμε να πάμε 2 commits πίσω με την εντολή `git checkout HEAD~2`.

Για να επιστρέψουμε στο τελευταίο branch που ήμασταν πριν το checkout, μπορούμε να κάνουμε χρήση της εντολής `git switch -`.

### Discarding changes

### checkout

Αν για οποιοδήποτε λόγο θέλουμε να κάνουμε discard τις όποιες αλλαγές έχουμε κάνει σε ένα αρχείο μας από το τελευταίο commit, μπορούμε να κάνουμε χρήση της εντολής `git checkout HEAD <filename>`. Έτσι θα επιστρέψουμε στο HEAD ακριβώς μετά το τελευταίο commit.

Αντίστοιχα λειτουργεί και η εντολή `git checkout -- <filename>` .

### restore

Η εντολή `git restore <filename>` έχει παρόμοια λειτουργικότητα με την checkout. Είναι μια πιο καινούργια εντολή, που όπως και η switch, σκοπεύει να απλοποιήσει κάποιες λειτουργίες αντί να γίνονται όλες με την checkout.

Η διαφορά της restore είναι ότι μας επιτρέπει να κάνει restore και να γυρίσουμε σε προηγούμενα commits, κάνοντας discard περισσότερες αλλαγές. Έτσι αντί να γυρίσουμε στο HEAD, μπορούμε να πάμε 1, 2, 3 κλπ commits πίσω με την εντολή `git restore --source HEAD~# <filename>`, όπου # ο αριθμός για το πόσα commits πίσω από το HEAD να πάμε. Αν αλλάξουμε γνώμη και δε θέλουμε τελικά να γυρίσουμε τόσο πίσω, μπορούμε να κάνουμε `git restore HEAD` και έτσι θα επιστρέψουμε πάλι στο HEAD.

Μία άλλη λειτουργικότητα της restore είναι η αφαίρεση ενός αρχείου από το staging area. Αν π.χ. κάνουμε κάποιο λάθος και κάνουμε stage ένα αρχείο που δε θέλουμε να γίνει commit, μπορούμε να το αφαιρέσουμε από το staging area με την εντολή `git restore --staged <filename>`.

### reset

##### soft reset
Αν για οποιοδήποτε λόγο θέλουμε να κάνουμε reset το repository σε μια προηγούμενη κατάσταση, χάνοντας όμως τα ενδιάμεσα commits, μπορούμε να χρησιμοποιήσουμε την εντολή `git reset <commit-hash>` (λειτουργεί και με το ` HEAD~#`). ΠΡΟΣΟΧΗ όμως, ενώ χάνονται τα commits και το HEAD είναι πλέον στο commit που γυρίσαμε, οι αλλαγές στα αρχεία παραμένουν! Αυτό μπορεί να φανεί χρήσιμο αν για παράδειγμα θέλουμε να κρατήσουμε τις αλλαγές αλλά τις θέλουμε σε ένα άλλο branch, κάνοντας π.χ. `switch` σε ένα άλλο και παίρνοντας τις αλλαγές μαζί μας (όπως είδαμε με τη switch).

##### hard reset

Αν θέλουμε να κάνουμε reset ΚΑΙ τις αλλαγές, πρέπει να χρησιμοποιήσουμε την επιλογή `--hard` με την εντολή `git reset --hard <commit>` (λειτουργεί και με το `<commit-hash>`), π.χ. `git reset --hard HEAD~2`.

### revert

Είναι παρόμοια με το `git reset` όσον αφορά το τι κάνει (undo changes), αλλά το κάνει με διαφορετικό τρόπο. Η `reset` μεταφέρει το branch pointer (HEAD) προς τα πίσω και σβήνει τα ενδιάμεσα commits. Η revert από την άλλη δημιουργεί ένα νέο commit στο οποίο έχουν γίνει τα reverses/undos. Tο commit που θέλουμε να κάνουμε revert/undo δε χάνεται, υπάρχει ακόμα στο log, όμως στο νέο commit που θα προκύψει από τη revert, οι αλλαγές από το reversed commit έχουν πια χαθεί. Επειδή είναι νέο commit, θα χρειαστεί να βάλουμε και κάποιο μήνυμα. Αυτό επιτυγχάνεται με την εντολή `git revert <commit_hash>`.

### Ποια η χρησιμότητά τους και πότε επιλέγουμε το καθένα

Η `revert` είναι χρήσιμη όταν θέλουμε να κάνουμε reverse τα commits κάποιου άλλου. Η `restore` είναι χρήσιμη όταν θέλουμε να κάνουμε reverse τα δικά μας commits που δεν έχουμε κάνει share με άλλους.
